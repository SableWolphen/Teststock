TESTSTOCK STRATEGY CHANGE LOG

2026-08-22 — BOUNDED MULTI-SOURCE DECISION INTELLIGENCE
- Added a transparent stock decision overlay combining real-time multi-stock ranking, setup-specific backtest diagnostics, technical quality, sample-shrunk pattern confidence, screener-style fundamentals/liquidity state, portfolio correlation penalties and opportunity decay.
- The overlay can only rerank, reduce, expire or block candidates that already passed the existing Teststock path. It cannot create eligibility, increase maximum risk, loosen regime or safety gates, change the two-tournament architecture, or bypass exact per-order stock approval.
- Preserved shadow-first profitability admission and Robinhood-confirmed real-fill learning. The fast refresh now runs profitability admission as well as the deep scan, closing a prior workflow consistency gap.
- Added dashboard cards for decision score, pattern confidence, setup backtest depth, fundamentals/liquidity status, correlation, admission state and freshness decay. Unknown inputs remain visibly unknown rather than being treated as a pass.
- Updated architecture validation to match the existing selective multi-position mode and explicitly verify continued scanning and per-order approval.
- Closed the Claude handoff gaps: stock BUY triggers now require an admitted profitability state plus a decision-overlay pass; crypto entry zones remain in the direct API lane and cannot enter Claude dispatch; and wake/trigger instructions consistently require ticker-specific approval before every stock order.
- Research refreshes now rebuild and validate the trigger board and Claude dispatch before publishing, avoiding the normal GitHub Actions bot-commit delay between a fresh signal and its execution packet.

2026-08-21 — CALM REGIME RETUNING WITHOUT HOLDOUT LEAKAGE
- Reworked entry-gate validation so CALM threshold selection no longer uses either untouched holdout for tuning. Pre-2024 development is split into 2018-2021 training and 2022-2023 calibration; the lowest CALM score threshold that clears the calibration gates with adequate sample size is selected, while 2024-2025 and 2026+ remain untouched confirmation slices.
- Added CALM loss diagnostics by setup type, sector, year and per-trade loss rows. Setup/sector exclusions are allowed only when the same subgroup is persistently weak in both training and calibration with minimum sample support; time-period clustering is reported for diagnosis but is not used as a prospective exclusion.
- MIXED is now a deliberately disabled regime for new stock signals because its development record is non-viable. It is no longer treated as a candidate for automatic recovery through looser or reduced sizing.
- VOLATILE, TRENDING_DOWN and UNKNOWN remain reduced-size when untouched samples are sparse rather than being declared strategy failures from tiny samples.
- TRENDING_UP remains enabled and is marked as the highest research priority because both untouched holdout slices currently confirm it.

2026-08-20 — FULL LIVE CANDIDATE QUEUE MONITORING
- Fixed the non-LLM trigger monitor so it watches the complete qualified stockCandidateQueue as well as stockOrders. Reserve/fallback candidates can now generate BUY_TRIGGER events when they are fresh and inside their encoded buy zones.
- Candidate rows are de-duplicated by ticker, ranked by queueRank, and still preserve A-before-B priority. This fixes the case where a live tournament champion existed in the reserve queue but the trigger board ignored it.
- No safety gates were loosened: stale research still cannot trigger a buy, maximumEntry/no-chase still applies, and Claude must still pass live Robinhood cash, account-floor, spread, gap, correlation, protection and other hard guards.

This file records changes to trading RULES, thresholds, tiers, sizing, validation, and safety behavior. Routine market-data refreshes and changing trade signals are intentionally not listed here.

2026-08-19 — TARGET2 REWARD/RISK + COST-ADJUSTED CROSS-ASSET RANKING
- Fixed the stock optimizer's reward/risk qualification metric. The minimum reward/risk gate now uses target2 (the full planned target), while target1 remains a partial-profit/de-risking milestone. This removes the unintended conflict where a deliberately closer target1 could block a setup that actually met the full-target asymmetry requirement.
- Removed the optimizer's leftover two-stock candidate cap. The optimizer can now consider up to four independently qualified stock allocations, consistent with the newer portfolio/frequency rules.
- Added conservative cost-adjusted stock expectancy. A planning allowance for round-trip execution friction is converted into R and subtracted from conservative expectancy before eligibility and ranking. This is a conservative planning estimate, not a claim that exact future costs are known.
- Added portfolioOpportunityScore so stock candidates are prioritized using quality, cost-adjusted expectancy, target2 reward/risk, validation depth, liquidity when available, and volatility rather than simple quality score alone.
- Fixed regime inference in the multi-opportunity expansion pass and made regime-profile gating use cost-adjusted expected R when available.
- Added cross-asset opportunity ranking across already-qualified STOCK, OPTION, and CRYPTO research candidates. The ranking is priority only: it never overrides live broker/account, whole-contract, event, real-fill, entry, spread, gap, protection, cash, correlation, frequency, or risk checks and never creates a trade quota.
- Probability-first stock and option gates now explicitly check cost-adjusted expectancy when available.
- Cross-asset ranking is now a required signal-health dependency so missing ranking data fails closed instead of silently using a more aggressive fallback.
- Signal schema advances to v19 after the next successful scan/build.

2026-08-19 — MULTI-OPPORTUNITY + SECOND HOLDOUT + GAP/LIQUIDITY GUARDS
- Added stricter regime-specific entry profiles for trending-up, calm, volatile, trending-down, mixed, and unknown markets.
- Validation now separates development history, a 2024-2025 untouched holdout, and a second untouched confirmation holdout beginning 2026-01-01. Weak untouched-regime evidence blocks or reduces that regime; sparse second-holdout evidence reduces size instead of increasing risk.
- Added breadth confirmation so a bullish setup is less trusted when participation across the stock universe is weak.
- Added symbol probation. Lightly tested symbols start smaller and require deeper historical/real-fill evidence before normal sizing.
- Added runtime opening-gap guard. A gap above 4% absolute or consuming over 50% of planned entry-to-stop distance requires skipping or revalidation after the open; stops may never be widened to make the trade fit.
- Added liquidity preference and tightened the stock spread hard cap to 0.35%. When otherwise comparable candidates exist, tighter spreads, higher reliable dollar volume, and cleaner real fills are preferred.
- Expanded opportunity capacity: up to 4 concurrent Teststock positions, up to 3 new positions per day, and up to 10 new positions in rolling 7 days. Options remain capped at 1 new option/day and crypto at 1 new crypto/day. These are maxima, not trade quotas; all total-risk, cash, correlation, event, execution, protection, and circuit-breaker rules still apply.
- Margin remains DISABLED. The user would accept margin only if it cannot lose money; no real margin position can satisfy that condition. Teststock therefore continues to use only non-margin cash buying power and may not create a margin debit or borrow funds.
- Signal schema advances to v18 after the next successful scan/build.

2026-08-19 — PROBABILITY-FIRST STOCKS + EVIDENCE-GATED OPTIONS/CRYPTO
- Added a probability-first overlay that runs after the existing Teststock stock/options/crypto plans and may only make them stricter.
- Stocks are now the default growth engine. New stock allocations must meet at least 20 historical samples, 55% historical win rate, 0.60 conservative expected R, 2.5:1 reward/risk, growthQuality >= 92, and controlled volatility. Higher volatility automatically cuts size. A single new stock is capped near 1.5% planned stop risk of the reference sleeve and combined new-stock planned stop risk near 2.5%, before smaller live-account limits.
- Options remain exceptional. In addition to all existing elite, event, spread, whole-contract, tier, protection, and broker checks, options now require an underlying with growthQuality >= 97, at least 25 historical samples, at least 62% historical win rate, conservative expected R >= 0.90, reward/risk >= 3, plus at least 10 resolved real Teststock trades overall with average realized R >= 0.25 and win rate >= 50% before Claude may execute a new option.
- Crypto remains optional. A/A+ setups now require at least 15 historical samples, positive historical average forward move, A+ win rate >= 60% or A win rate >= 55%, and altcoins require a positive BTC trend. A+ reference allocation is capped near 40% with ~2% planned stop risk; A near 20% with ~1% planned stop risk, before smaller live-account limits.
- Before Claude may execute a new crypto position, the overall real-fill sample must also have at least 10 resolved real Teststock trades, average realized R >= 0.25, and win rate >= 50%. If broker crypto order tools are unavailable at runtime, crypto remains signal-only.
- Missing probability-first policy is now a critical dependency: fail closed and open no new position rather than silently falling back to more aggressive behavior.
- Signal schema advances to v17 after the next successful scan/build.

2026-08-19 — PERFORMANCE-GATED RISK SCALING
- Added performanceScalingGuard so account equity alone can never unlock more aggressive trading risk.
- The normal capital ladder still selects the equity tier, but Claude must also compute an effective risk tier from confirmed real-money performance and use the more conservative settings.
- Before SCALE risk can be used, Teststock requires at least 20 resolved real trades, average realized R >= 0.20, win rate >= 45%, reliable observed drawdown below 6% when available, and no active real-fill, slippage, protection, health, persistence, or circuit-breaker block.
- Before GROWTH risk can be used, Teststock requires at least 30 resolved real trades, average realized R >= 0.30, win rate >= 48%, reliable observed drawdown below 6%.
- Manual deposits or account profits may raise the equity tier but cannot by themselves unlock higher risk. Missing or ambiguous performance evidence never unlocks more aggression.
- Signal schema advanced to v16.

2026-08-19 — SYSTEM HEALTH + PERSISTENCE + EXECUTION TELEMETRY
- Added machine-readable systemHealth policy to signal.json. Critical dependencies now fail closed: stale/missing/contradictory Teststock data, unknown Robinhood balances/orders/positions, failed journal/history reconciliation, or unavailable required protective-exit capability means no new position.
- Added a visible System Health dashboard to the public Teststock page. GitHub-side signal/validation status is shown directly; Robinhood, protective-exit, and journal-persistence checks are clearly marked as runtime checks rather than guessed.
- Added a cross-run journal persistence self-test using a nonce. Claude may mark the journal PERSISTENT only after a later scheduled run reads back the same nonce. Failed/unverified persistence falls back to Robinhood-history reconstruction and may never justify more risk.
- Expanded real-fill execution telemetry to include order type/price, bid/ask spread at submission when available, time-to-fill, adverse slippage, protective-order creation/verification timing, and protection latency. Missing telemetry remains unknown rather than inferred.
- Added a protective-order reliability guard: if enough recent supported stock/option entries exist and verified protection falls below 90%, pause new stock/option entries until reliability is restored.
- Added one concise daily summary policy covering account value, cash, positions, planned risk, realized P&L, trades, regime, blocked setups, system health, and journal persistence.
- Added a minimum shadow-evidence rule: at least 30 resolved ACCEPTED and 30 resolved REJECTED shadow decisions are required before shadow results can justify even a manual gate-review discussion. Shadow data can never automatically loosen live-money rules.
- Signal schema advanced to v15 and signal validation now requires fail-closed health metadata, execution-telemetry source-of-truth, daily-summary policy, and shadow sample floors.

2026-08-19 — HOLDOUT VALIDATION + REGIME-SPECIFIC RISK + EVENT/SLIPPAGE/SHADOW GUARDS
- Entry-gate validation now uses a chronological development period and an untouched holdout period beginning 2024-01-01. The fixed 52% historical win-rate, 2.5:1 reward/risk, 15-sample, and 0.5R conservative-expected-value thresholds are not tuned on the holdout.
- Validation now publishes a runtime policy separately for calm, volatile, trending-down, trending-up, mixed, and unknown regimes. Weak holdout regimes can block new risk; sparse regimes automatically reduce size and block options. Regime validation may only reduce risk, never loosen the base gates.
- Added event-risk blackouts before new positions: high corporate-action risk blocks entries; stock entries are blocked around the estimated report window from 3 days before through 1 day after; options use a stricter 7-day pre-event window through 1 day after. Estimated dates remain uncertain, so the guard is intentionally conservative.
- Added real-fill adverse-slippage learning. With enough confirmed fills, repeated bad execution can reduce size or block the exact stock/option/crypto setup, cluster, or symbol bucket. Robinhood fills remain authoritative.
- Added a paper shadow ledger that tracks both accepted and rejected Teststock candidates and later measures modeled R/opportunity cost from future Alpaca bars. Shadow results are diagnostic only and can never automatically increase live-money risk or override Robinhood real-fill results.
- Claude scheduled instructions now explicitly apply holdout-regime scaling, event blackouts, slippage learning, and the rule that shadow data cannot be treated as real P&L.
