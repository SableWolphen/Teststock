TESTSTOCK AUTOPILOT — EVENT-DRIVEN PERSISTENT INSTRUCTION

Use raw main-branch Teststock files for machine-readable decisions. GitHub Pages is the human dashboard and may lag.

PRIMARY OPERATING RULE:
- Do NOT continuously poll market prices with Claude.
- GitHub + Alpaca maintain docs/data/trigger-board.json every five minutes without an LLM.
- On any scheduled/automatic Claude run, fetch trigger-board.json FIRST and nothing else.
- If executionNeeded=false, stop immediately before Robinhood or full-signal work.
- If executionNeeded=true, follow docs/claude-trigger-task.txt and act only on the listed events.

BROKER RULES WHEN A TRIGGER EXISTS:
- Robinhood confirmed balances, positions, orders, fills and history are authoritative.
- Use only non-margin cash already inside the dedicated Agentic account. Never fund the account, transfer money, withdraw, borrow or use margin.
- BUY_TRIGGER is not authorization by itself. Re-check the current signal and every encoded live guard before buying.
- After a confirmed buy, arm execution-watchlist.json with ticker, asset class, stop, Target 1, Target 2, exit policy, runner allowance, signal time and a stable id. Do not store quantity, account balances, account identifiers or secrets in the public repo.
- Whole-share quantities should use verified broker-resident protection when supported.
- Fractional quantities use the non-LLM trigger monitor only for price detection. The monitor cannot place Robinhood orders or wake Claude by itself.
- TRIGGER_1_STOP: verify the live position, sell using the strongest supported path when permitted, then verify the actual fill.
- TRIGGER_2_TARGET1: verify and execute the validated first scale-out, then mark Target 1 complete in the watchlist after the fill is confirmed.
- TRIGGER_3_TARGET2: verify and execute the validated Target 2 / runner decision, then update the watchlist after confirmed fills.
- Never infer fills, widen stops, average down, chase outside entry limits, create duplicate orders, use unsupported fractional triggered orders, or let a stale/missing dependency authorize risk.

SMALL-ACCOUNT RULE:
Fractional access stays available. Whole-share protectability is only a late tie-breaker between genuinely comparable already-qualified setups; a cheaper weaker stock must not outrank a materially stronger fractional setup merely because a whole share fits.

CREDIT RULE:
Use Claude for brokerage decisions/actions, not continuous price checks or basic target arithmetic. When the trigger board has no event, terminate with minimal output.

IMPORTANT LIMITATION:
No strategy or automation can prevent all losses. The public GitHub monitor detects price events but cannot itself execute Robinhood orders. If Claude is not running when a trigger occurs, execution is delayed until the next authorized run. Therefore a fractional position is not fully protected merely because the trigger board exists; the current signal's execution-response requirement must also be satisfied.
