TESTSTOCK AUTOPILOT — SCHEDULED CLAUDE TASK

Run this task once per hour.

1. Read https://sablewolphen.github.io/Teststock/signal.json
2. Read the connected Robinhood Agentic account and treat its current non-margin cash buying power, positions, and open orders as the only source of truth for available money. Do not use a fixed $50/$100/$200/$500 Teststock budget.
3. Convert Teststock's allocationPctOfRobinhoodBuyingPower or maxRiskPctOfRobinhoodBuyingPower into a dollar amount using the live Robinhood cash buying power immediately before any new order.
4. If the signal is stale, expired, CASH, WAIT, WAIT_FOR_TRIGGER, WAIT_FOR_MARKET_OPEN, DO_NOT_TRADE, DO_NOT_CHASE, or otherwise non-actionable, do nothing and end the task.
5. If a stock is AUTO_BUY_ELIGIBLE, verify market status, live executable price, buying power, existing positions, and open orders. Trade only if every Teststock hard rule remains satisfied and never exceed the calculated percentage-based allocation.
6. If an option is AUTO_BUY_ELIGIBLE, trade it only if eliteOption exists, every elite check is still true, the exact contract is available, live spread/liquidity remain acceptable, and the premium/risk fits inside maxRiskPctOfRobinhoodBuyingPower. Never substitute a different option merely to force a trade.
7. Never use margin, borrowed money, naked options, short stock, undefined-risk options, leveraged crypto, averaging down, or wider stops.
8. Never duplicate an existing position or open order. Re-read Robinhood buying power after any fill before sizing another trade.
9. Manage existing Teststock positions using their saved invalidation and targets. If invalidation is breached, exit according to the supported Robinhood tools. At target1, protect gains or take partial profit according to Teststock's policy. At target2, prioritize profit capture. Never move a stop farther away to avoid realizing a loss.
10. If outcome/drawdown locks are active, obey them. If Teststock and Robinhood disagree materially, do not trade.
11. Crypto may be executed only if the connected Robinhood MCP explicitly exposes supported crypto order-placement tools at runtime. Otherwise keep crypto signal-only. Never fabricate execution.
12. Do not increase risk because of a profit target, losing streak, or desire to reach a goal faster. Unused buying power stays cash.
13. If no action is required, report only a short status such as "No eligible Teststock trade this run." If a trade or exit occurs, report the symbol, action, live Robinhood dollar amount used, execution price if available, stop/invalidation, targets, and remaining buying power.

This task is intended to be hands-off, but it must always obey live Robinhood permissions and the current hard rules in Teststock signal.json.
