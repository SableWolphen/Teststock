TESTSTOCK AUTOPILOT — SCHEDULED CLAUDE TASK

Run this task once per hour.

1. Read https://sablewolphen.github.io/Teststock/signal.json and follow its current hardRules, capitalLadder, profitLock, circuitBreakers, executionQuality, portfolioGuard, outcomeGuard, assetClassRouting, entries, stops, and targets exactly.
2. FUNDING LOCK: use only cash and trading proceeds already inside the dedicated Robinhood Agentic account. Never initiate a deposit, ACH transfer, debit-card transfer, wire, bank transfer, internal transfer, withdrawal, or any other movement of money. Only the user may manually add more money.
3. Read live Robinhood Agentic-account equity, NON-MARGIN CASH BUYING POWER, positions, open orders, and reliable account performance/history if the connected tools expose it.
4. Select exactly one capitalLadder tier from live Agentic-account equity. Apply that tier before sizing every new trade. Never exceed maxDeployedPct or the tier planned-stop-risk limit. If the tier disables options, do not open an option.
5. PROFIT LOCK: select the active profitLock floor from live account equity. Estimate total planned stop-loss across existing Teststock positions plus the proposed trade. Do not intentionally size a new trade so that equity minus total planned stop-loss would fall below the active protected floor. This is a planning rule, not a guarantee against gaps/slippage.
6. CIRCUIT BREAKERS: if reliable Robinhood history is available and current-day loss is 3% or more, or 7-day drawdown is 6% or more, open NO NEW POSITIONS. Continue protective exits and position management. If the necessary history is unavailable, do not invent it; fall back to Teststock outcomeGuard and capitalLadder.
7. Keep asset classes separate: STOCK=stockPlan.stockOrders only; OPTION=stockPlan.eliteOption only; CRYPTO=cryptoPlan.cryptoOrders only. Never substitute across asset classes.
8. If a signal is stale, expired, WAIT, WAIT_FOR_TRIGGER, WAIT_FOR_MARKET_OPEN, DO_NOT_TRADE, DO_NOT_CHASE, or otherwise non-actionable, do nothing for that asset class.
9. STOCK: buy only AUTO_BUY_ELIGIBLE orders that still pass the live entry range. Size with the SMALLEST amount allowed by Teststock allocation after the capital-ladder multiplier, the active tier stop-risk cap, maxDeployedPct, profitLock floor, remaining non-margin cash, and portfolioGuard. Teststock expectancy, adaptivePerformance, historical sample, reward/risk, market, sector, intraday, freshness, and entry gates must remain satisfied.
10. OPTION: stocks/cash are the default. Buy only when eliteOption is AUTO_BUY_ELIGIBLE, every elite check remains true, the active tier allows options, the exact contract exists, and total premium/risk is no more than the smaller of eliteOption.maxRiskPctOfRobinhoodBuyingPower and the active tier maxOptionRiskPct. Never substitute a lottery contract. If no exact affordable contract fits the cap, skip the option.
11. CRYPTO: use only cryptoPlan.cryptoOrders. A+ is the stronger setup; A is intentionally smaller and must never be promoted to A+ sizing. Only one Teststock crypto position may be open at a time. Execute only if the order is in its valid buy zone AND the connected Robinhood tools explicitly expose crypto order placement at runtime. Otherwise keep crypto signal-only.
12. EXECUTION QUALITY: prefer limit orders when the connected tool supports them. Never pay above maximumEntry. Skip a new STOCK entry if live spread is over 0.5%, OPTION entry if spread is over 10%, or CRYPTO entry if spread is over 0.75%. Also skip when executable pricing is materially worse than the Teststock signal. Missing a trade is better than a bad fill.
13. Never use margin, borrowed money, naked options, short stock, undefined-risk options, leveraged crypto, averaging down, adding to losers, wider stops, duplicate positions, or duplicate open orders.
14. PORTFOLIO GUARD: count existing positions and open orders before a new entry. Do not open more than two new Teststock positions in one run. Existing planned risk counts against the new trade. Never duplicate the same ticker or option contract.
15. Obey outcomeGuard: weak recent resolved performance or multiple consecutive losses reduce size, lock options, or pause new trades. A paused guard means no new entries.
16. Manage existing Teststock positions from saved invalidation and targets. Exit when invalidation is breached. At target1 protect gains or take partial profit; at target2 prioritize profit capture. Never widen risk.
17. Re-read buying power/equity after fills before sizing another trade. If Teststock and Robinhood materially disagree, do nothing.
18. Never increase risk to chase a profit target, recover losses, or make the account grow faster. Unused buying power stays cash.
19. If no action is required, report only a short status. If a trade or exit occurs, report ASSET CLASS, symbol/contract, action, dollar amount/risk used, execution price if available, active capital-ladder tier, active protected-equity floor, stop/invalidation, targets, and remaining buying power.

The account may start with $100 and may use profits or later user-added deposits, but the agent itself must never fund the account. No strategy guarantees profit or prevents loss.
