TESTSTOCK AUTOPILOT — SCHEDULED CLAUDE TASK

Run this task once per hour.

1. Read https://sablewolphen.github.io/Teststock/signal.json and follow its current hardRules, hardAccountFloor, capitalLadder, profitLock, circuitBreakers, tradeFrequencyGuard, correlationGuard, executionQuality, exitAutomation, healthGuard, portfolioGuard, outcomeGuard, assetClassRouting, entries, stops, and targets exactly.
2. Read https://sablewolphen.github.io/Teststock/real-fill-learning-policy.txt and apply it before any new entry. Maintain a persistent file named Teststock-Real-Trades.json in this Cowork project/task workspace using https://sablewolphen.github.io/Teststock/teststock-real-trade-journal-template.json as its schema. If that file is missing, create it from the template. Robinhood history is always authoritative over the journal.
3. REAL-FILL RECONCILIATION: before considering a new trade, reconcile Teststock-Real-Trades.json against Robinhood Agentic order history, option order history, positions, closed positions, and activity/history exposed by the connected tools. Use stable Robinhood order IDs to avoid duplicates. Never infer a fill from an order submission or a target/stop touch. Record actual average entry and exit fills, quantity/contracts, realized P&L, realized return, realized R when reliable, adverse entry/exit slippage when a reliable reference exists, exit reason, protective-order IDs/status, setupType, riskCluster, and whether the position is still open. Unknown or partial records must remain UNKNOWN/OPEN and may never justify more risk.
4. JOURNAL PERSISTENCE SELF-TEST: use the journal persistence.testNonce field. If persistence is UNVERIFIED, write a new unique nonce and timestamp. On a later scheduled run, verify the exact same nonce is still present before marking PERSISTENT. If it is missing, changed unexpectedly, or the journal cannot be saved/read across runs, mark persistence FAILED/UNVERIFIED. Reconstruct recent statistics from Robinhood history and do not use missing persistence to increase risk. Report a persistence problem prominently but briefly.
5. REAL-FILL LEARNING: recompute overall journal statistics AND separate bySetupType, byRiskCluster, and bySymbol statistics after reconciliation. Apply the current real-fill-learning-policy to the overall pool and to any bucket with enough resolved trades/fills. Weak realized R, win rate, adverse slippage, or poor protective-order reliability may reduce size, block a bucket, or pause stock/options even when the aggregate pool looks acceptable. Real-fill learning may make the system more conservative, never more aggressive than Teststock's other limits.
6. FUNDING LOCK: use only cash and trading proceeds already inside the dedicated Robinhood Agentic account. Never initiate a deposit, ACH transfer, debit-card transfer, wire, bank transfer, internal transfer, withdrawal, or any other movement of money. Only the user may manually add more money.
7. Read live Robinhood Agentic-account equity, NON-MARGIN CASH BUYING POWER, positions, open orders, order status, and reliable account/order history if the connected tools expose it.
8. HARD FLOOR: if live Agentic-account equity is below $75, open no new positions. Manage/protect/close existing positions only. Never auto-fund. New-trade eligibility may resume only once live equity is at least $80 and every other rule passes.
9. CAPITAL-LADDER BOUNDARIES ARE EXACT AND LOWER-BOUND INCLUSIVE: equity >= $0 and < $80 = RECOVERY; equity >= $80 and < $100 = DEFENSE; equity >= $100 and < $125 = PROVE; equity >= $125 and < $150 = SCALE; equity >= $150 = GROWTH. Therefore exactly $80 is DEFENSE, exactly $100 is PROVE, exactly $125 is SCALE, and exactly $150 is GROWTH. Never choose the lower tier at an exact boundary. Select exactly one tier from live Agentic-account equity before sizing every new trade. Never exceed maxDeployedPct or the tier planned-stop-risk limit. If the tier disables options, do not open an option.
10. PROFIT LOCK: select the active profitLock floor from live account equity. Estimate total planned stop-loss across existing Teststock positions plus the proposed trade. Do not intentionally size a new trade so that equity minus total planned stop-loss would fall below the active protected floor.
11. CIRCUIT BREAKERS: if reliable Robinhood history is available and current-day loss is 3% or more, or 7-day drawdown is 6% or more, open NO NEW POSITIONS. Continue protective exits and position management. If the necessary history is unavailable, do not invent it.
12. TRADE FREQUENCY: if reliable order history is available, do not exceed 2 new Teststock positions in one calendar day, 6 new Teststock positions in rolling 7 days, or 1 new option position in one calendar day. Protective sells/exits do not count. If history is ambiguous, use the safer interpretation.
13. CORRELATION: avoid stacking the same bet. Do not open more than one new position from the same Teststock correlationGuard risk cluster. Existing highly correlated exposure can make a new entry smaller or ineligible.
14. ENTRY-GATE ROBUSTNESS: inspect signal.entryGateRobustness and the stockPlan.policy runtime-regime/holdout validation fields before new stock/option risk. The fixed 52% win-rate, 2.5:1 reward/risk, 15-sample, and 0.5R conservative-expected-value gates must not be loosened because of a favorable recent slice. A weak holdout regime can reduce size, block stocks, or block options. A sparse/unknown regime must never justify more risk.
15. EVENT BLACKOUT: obey the stockPlan.policy event-risk policy and advanced event blocks already encoded into the current signal/plan. Do not bypass a stock blackout around an estimated earnings/filing window or high corporate-action risk. Options use the stricter encoded event window. If the event date is uncertain, use the safer encoded decision rather than guessing the event away.
16. CRITICAL DEPENDENCY FAIL-CLOSED: before every new entry, verify the current Teststock signal is fresh, live Robinhood equity/cash is readable, positions and open-order state are known, the proposed position is not duplicated, journal reconciliation succeeded or reliable Robinhood-history reconstruction succeeded, and required protective-exit capability is available for a new stock/option. If any critical dependency is missing, stale, contradictory, or unknown, OPEN NO NEW POSITION. Cash is the correct result. Continue managing/protecting existing exposure when possible.
17. Keep asset classes separate: STOCK=stockPlan.stockOrders only; OPTION=stockPlan.eliteOption only; CRYPTO=cryptoPlan.cryptoOrders only. Never substitute across asset classes.
18. If a signal is stale, expired, WAIT, WAIT_FOR_TRIGGER, WAIT_FOR_MARKET_OPEN, DO_NOT_TRADE, DO_NOT_CHASE, or otherwise non-actionable, do nothing for that asset class.
19. STOCK: buy only AUTO_BUY_ELIGIBLE orders that still pass the live entry range. Size with the SMALLEST amount allowed by Teststock allocation after holdout-regime scaling, event guards, capital-ladder multiplier, real-fill-learning/slippage reductions, active tier stop-risk cap, maxDeployedPct, profitLock floor, remaining non-margin cash, trade-frequency guard, correlation guard, and portfolioGuard. Never loosen a failed gate.
20. OPTION: stocks/cash are the default. An eliteOption may arrive as RUNTIME_WHOLE_CONTRACT_CHECK_REQUIRED instead of AUTO_BUY_ELIGIBLE. This is NOT permission to buy yet. First confirm every elite check remains true, event/holdout rules permit options, real-fill learning has not locked options, the active tier allows options, the exact contract exists, and live spread/liquidity is acceptable. Then calculate liveAllowedOptionRiskDollars = live Agentic-account equity × min(eliteOption.maxRiskPctOfRobinhoodBuyingPower, active tier maxOptionRiskPct) / 100. Compare that with the ACTUAL maximum dollar risk/premium of the smallest tradable quantity, normally one whole contract. Only if one whole contract fits inside the live dollar cap may the option become executable. If one contract costs/risks too much, SKIP IT. Never pretend a percentage allocation can buy a fraction of an options contract and never substitute a lottery contract.
21. CRYPTO: use only cryptoPlan.cryptoOrders. A+ is stronger; A is intentionally smaller and must never be promoted. Only one Teststock crypto position may be open at a time. Execute only if the connected Robinhood tools explicitly expose crypto order placement at runtime; otherwise keep crypto signal-only.
22. EXECUTION QUALITY + LIVE TELEMETRY: prefer limit orders when supported. Never pay above maximumEntry. Skip a new STOCK entry if live spread is over 0.5%, OPTION entry if spread is over 10%, or CRYPTO entry if spread is over 0.75%. Skip materially worse executable pricing. When runtime data is available, record submitted order type/price, bid/ask spread at submission, confirmed fill time and price, time-to-fill, adverse slippage, protective-order creation/verification time, and protection latency. Never invent missing telemetry. Apply real-fill slippage/reliability reductions or blocks when the policy says to.
23. AUTOMATIC PROTECTIVE EXIT: a new STOCK or OPTION entry is not considered complete until a persistent protective exit is created and verified. After a fill, immediately place the strongest supported persistent protective sell at the saved Teststock invalidation. Verify it is accepted and covers the full live quantity. If the connected tool cannot create or verify protection, do not open that new position.
24. Do not assume bracket/OCO support. Before taking partial profit or replacing protection, inspect open sell orders, cancel/replace conflicts, verify remaining quantity, and never create sell orders totaling more than the live position.
25. AUTOMATIC PROFIT MANAGEMENT: at target1, protect gains and take partial profit when practical; protect the remainder at breakeven or tighter without widening risk. At target2, prioritize taking profit on most or all of the remaining position unless the current signal explicitly provides a tighter trailing plan.
26. Never use margin, borrowed money, naked options, short stock, undefined-risk options, leveraged crypto, averaging down, adding to losers, wider stops, duplicate positions, or duplicate open orders.
27. PORTFOLIO GUARD: count existing positions and open orders before a new entry. Do not open more than two new Teststock positions in one run. Existing planned risk counts against the new trade.
28. Obey outcomeGuard. Weak recent resolved performance or multiple consecutive losses reduce size, lock options, or pause new trades.
29. SHADOW DATA IS DIAGNOSTIC ONLY: Teststock may publish accepted/rejected paper-shadow outcomes to study opportunity cost and overly strict gates. Never treat a shadow win as a real fill, never add it to Robinhood P&L, and never automatically loosen a live-money rule because rejected shadow trades later did well. Do not even recommend a gate change from shadow performance until at least 30 ACCEPTED and 30 REJECTED shadow decisions are resolved; after that, shadow results can trigger a review only, not automatic risk increases.
30. HEALTH GUARD: if Teststock is stale, Robinhood tools are unavailable, order status is unknown, buying power/equity is missing, a protective order cannot be verified, journal/history reconciliation is unavailable, or an unexpected partial fill/duplicate appears, open no new positions. Safely manage existing exposure first.
31. Re-read buying power/equity and positions after every fill. Reconcile the real-trade journal after every confirmed entry, partial exit, final exit, cancellation, or protective-order change. If Teststock and Robinhood materially disagree, do nothing.
32. DAILY SUMMARY: once per calendar day, on the first scheduled run at or after 08:00 local time when local time is available (otherwise first run of each UTC calendar day), produce one concise daily summary and add it to dailySummaries if persistence works. Include account value, cash, open positions, planned open risk when reliable, realized P&L, trades today, current regime, blocked setups, system health, and journal-persistence status. Do not repeat the same daily summary date.
33. Never increase risk to chase a profit target, recover losses, or make the account grow faster. Unused buying power stays cash.
34. RULE CHANGE VISIBILITY: when asked whether the strategy itself changed, read https://sablewolphen.github.io/Teststock/strategy-changelog.txt. Do not confuse a normal signal/market-data refresh with a strategy-rule change.
35. The user should not have to calculate entries, stops, exits, profit-taking, P&L, or journal statistics manually. If no action is required, report only a short status. If a trade or exit occurs, report ASSET CLASS, symbol/contract, action, actual fill, realized P&L when closed, realized R when reliable, active capital tier, protective-exit status, targets, remaining buying power, journal reconciliation/persistence status, system-health status, and any holdout/event/slippage/setup/cluster warning that applies.

The account may start with $100 and may use profits or later user-added deposits, but the agent itself must never fund the account. No strategy can guarantee profit or prevent loss. The objective is to improve risk-adjusted opportunity while failing closed whenever safety-critical information is missing.
