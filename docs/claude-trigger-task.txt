TESTSTOCK LOW-CREDIT TRIGGER EXECUTOR

Purpose: avoid using Claude for continuous market-price monitoring. GitHub + Alpaca maintain the trigger board. Claude should spend meaningful tokens only when a buy/sell action is actually pending.

FIRST AND CHEAPEST STEP ON EVERY RUN:
1. Fetch only this small raw file first:
   https://raw.githubusercontent.com/SableWolphen/Teststock/main/docs/data/trigger-board.json?cb=<current-utc-ms>
2. If monitorHealth is not OK, do not open new risk. If executionNeeded is false, STOP THE RUN immediately. Do not fetch the full Teststock signal, do not query Robinhood, do not analyze markets, and do not produce a long report.
3. If executionNeeded is true, inspect only the listed events. Then fetch the fresh raw signal, the execution watchlist, and the minimum Robinhood data necessary to verify and execute those events safely.

BUY_TRIGGER:
- A BUY_TRIGGER is only a wake-up signal, never automatic authorization by itself.
- Verify the latest full Teststock signal, GitHub pipeline health, live Robinhood cash/equity/positions/orders, spread, price drift, event/correlation/risk/frequency/protection gates, and unattended-trading permission.
- Buy only if every current live guard still passes.
- After a confirmed stock/crypto buy fill, arm docs/data/execution-watchlist.json with the SAVED stop, target1, target2, exit policy, runner allowance and a stable id. Never write quantity, account number, cash balance, or other private data to the public repository.
- If a fractional position cannot be successfully armed in the watchlist or the five-minute monitor is unhealthy, do not treat synthetic protection as active.

TRIGGER_1_STOP:
- Read the live Robinhood position and open sell orders for that ticker.
- If the live protected position still exists and the saved invalidation is reached, execute the strongest supported sell path immediately when permissions allow. Fractional quantities use the supported market sell path when triggered stops are unsupported.
- Re-read Robinhood and verify the fill. Never infer it.
- Mark the watchlist position CLOSED only after Robinhood confirms the full exit.

TRIGGER_2_TARGET1:
- Verify the live position and current validated exit plan.
- Execute the authorized Target 1 partial sale, reconcile conflicting protective orders, verify the fill, then set target1Completed=true in execution-watchlist.json.

TRIGGER_3_TARGET2:
- Verify the live position and fresh validated runner policy.
- Execute the authorized Target 2 sale. Keep only the runner currently allowed by the fresh signal and protection health; otherwise exit the remainder.
- Verify the fill and update target2Completed/status in execution-watchlist.json.

SAFETY / CREDIT RULES:
- Robinhood remains authoritative for fills, positions, quantities and money.
- The trigger board is public market-state detection only; it never proves that the user owns a position.
- Never use margin, borrowed funds, external funding, averaging down, widened stops or unsupported fractional trigger orders.
- Never use Claude to poll prices repeatedly when trigger-board executionNeeded=false.
- This repository does not contain an event bridge that can wake Claude instantly. If Claude is not running when a trigger appears, execution waits until the next authorized Claude run. Do not describe the system as instant or guaranteed protection.
